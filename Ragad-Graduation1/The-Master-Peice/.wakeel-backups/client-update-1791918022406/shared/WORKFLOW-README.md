# دورة المعاملات المشتركة — تجربة محلية

شغّل المشروع باستخدام VS Code Live Server من جذر The-Master-Peice، ثم افتح:
- العميل: Master-Client-Cycle/master-client-dash/client-dash.html
- إنشاء طلب: Master-Client-Cycle/master-creat-request/creat-request.html
- الوكيل: Master-Agent-Cycle/master-agent-dash/dashboard.html

يجب فتح الصفحات على نفس العنوان والمنفذ لتشترك في Local Storage. لا تستخدم file://.

## المسار

إنشاء طلب ومراجعة بياناته → المعاملات المطروحة → عرض الوكيل → قبول العميل → بانتظار الدفع → دفع تجريبي ناجح → معاملاتي قيد التنفيذ → إتمام الوكيل → الأرشيف والمستحقات بانتظار التسوية.

المسودات تبقى في معاملاتي ويمكن استكمالها. فشل الدفع أو إلغاؤه يبقي الطلب بانتظار الدفع. لا يمكن للوكيل بدء التنفيذ قبل نجاح الدفع. معالجة الدفع المكررة ممنوعة، والنتيجة المتأخرة لمحاولة ملغاة لا تبدأ التنفيذ. عند مغادرة صفحة الدفع تُلغى المحاولة المحلية؛ يمكن إلغاء أي محاولة تجريبية معلّقة من شاشة الدفع.

## البيانات والتواصل

المفتاح الحالي: wakeel_workflow_v2. يستورد أول تشغيل السجلات المحلية السابقة ويترك مفاتيحها الأصلية محفوظة؛ لا يُستورد التعديل اللاحق على المفاتيح القديمة بعد إنشاء السجل الحالي. بيانات الأدمن wakeel_admin_demo_v1 مستقلة.

يربط العميل والوكيل الطلبات والعروض والمدفوعات وهوية التواصل اللازمة. حساب واحد تجريبي من كل دور؛ هذا ليس نظام تسجيل دخول متعدد المستخدمين. ملف account-schema.js يوحّد الاسم والبريد ورقم الموبايل الأردني والمحافظة والنبذة، ويُستخدم في التسجيل والإعدادات. التحديث ينعكس على عرض الاسم وأزرار التواصل.

التواصل عبر wa.me وtel: من تفاصيل المعاملة. لا تُفتح الدردشة داخل المنصة. أرقام التواصل المفقودة وأرقام العينات الصفرية تعرض أيقونات معطّلة حتى تحديث رقم الحساب. المرفقات تحفظ اسم الملف ونوعه وحجمه فقط؛ لا يجري رفع محتواه.

التفضيلات والتقييمات وتذاكر الدعم الإضافية تحتفظ بوظائفها المحلية. نسخ بيانات العميل والوكيل متاحة على الجهاز نفسه؛ المشاركة بين أجهزة مختلفة تتطلب خادمًا.

## الدفع التجريبي

لا يتم تحصيل أموال أو تسديد فواتير. البطاقات خيارات اختبار، دون جمع رقم بطاقة حقيقية أو تخزين CVV:
- Visa 4242 أو Mastercard 4444: نجاح.
- Visa 0002: رفض.
- رمز التحقق التجريبي: 123؛ يُمسح بعد بدء المحاولة ولا يُحفظ.

يمكن إضافة وتحديث وحذف بطاقة وتعيين بطاقة افتراضية من إعدادات العميل. سجل الدفع يحتفظ بنسخة بيانات العرض والطريقة وقت السداد؛ تغيير البطاقة أو حذفها لا يغيّر الإيصال السابق.

مرجع الفاتورة DEMO-BILL خاص بمعاملة واحدة ومختلف عن البطاقة المحفوظة. ليس رقمًا صادرًا عن إي فواتيركم؛ تأكيده محاكاة محلية، ولا يمكن استخدامه خارج المشروع. المبلغ هو سعر العرض المقبول؛ لا تُضاف رسوم حكومية مفترضة.

payment-provider.js يوفّر الحد الفاصل للمحاكاة. الربط الفعلي لاحقًا يحتاج APIs مصادقة وصلاحيات وطلبات دفع على الخادم، tokenization عبر المزود، webhooks للتحقق من النتيجة، وإدارة تزامن وسجلات دائمة. لا تعتمد الإنتاج على Local Storage أو على قرار نجاح من المتصفح.

## دليل الجهات والخدمات

service-catalog.js وcatalogue-sources.json يحتويان الجهات والفروع والخدمات ومصادرها الرسمية، مع تاريخ مراجعة 2026-10-13. تُرشّح المديرية حسب الوزارة والمحافظة، ثم الخدمة حسب جهة تقديمها. المديرية المركزية التي تخدم المملكة موسومة بذلك، ولا يُفترض أنها فرع محلي لكل محافظة.

التغطية ليست حصرًا نهائيًا لكل فرع ومعاملة في الأردن. الفروع المضافة لها مصدر واضح؛ لا تُنشأ أسماء فروع لمجرد ملء القائمة. خيار «أخرى» يتيح تحديد المعاملة الدقيقة. راجع المصادر الرسمية عند توسيع الدليل أو قبل إطلاقه للإنتاج.

## التحقق

من جذر المشروع:
```
node shared/tests/workflow-model.test.cjs
node shared/tests/workflow-browser-qa.cjs
```

الفحص الأول يختبر منطق دورة الطلب والدفع والترحيل في ذاكرة مؤقتة دون تعديل بيانات المستخدم. الثاني يستخدم Edge على Windows وملف متصفح مؤقت وخادم 127.0.0.1، ويفحص العميل والوكيل على الكمبيوتر والهاتف، ويحفظ صورًا في مجلد مؤقت يطبعه عند الانتهاء. تُحجب الخطوط وLottie الخارجية فقط أثناء الاختبار ليعمل بشكل ثابت دون شبكة.

مكونات navbar وfooter وتنسيقات الصفحات الأساسية الحالية مستخدمة كما هي. flow.css يضيف تنسيقات مخصصة للقوائم والاتصال والدفع والصفحة المطروحة.
